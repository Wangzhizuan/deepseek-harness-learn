术语表 ​

这页解决什么问题 ​

DeepSeek Harness 的术语密度很高，而且很多词在别的项目里意思不一样（Fiber 不是 React 的 Fiber，Service 不是微服务，turn 不等于"一次对话"）。这页是全站术语的唯一权威页：其他页面用到的每个术语都以这里的定义为准，比喻说法也以这里为准。

用法：Ctrl-F 找词，看第 4 列的一句话解释，然后按第 5 列的锚点去源码确认。第 3 列的比喻只用于第一次建立直觉，写代码、写文档、跟同事讨论时请用第 1、2 列。 比喻在哪些地方会失真，见 /harness-explained 的"比喻的限制"段。

六层术语怎么互相咬住 ​

图说明：读术语表时按这个方向读最省力。① 是词汇的地基（所有层的词最终都落在 Context 上）；② 决定哪些词今天真的存在；③ 是词汇最密集的一层；④ 和 ⑤ 都由 ③ 派生。注意 ⑤ 回指 ①——能力接缝的 Service Definition 本质就是往 Context 上挂一个 Service，这条回边是全站最容易漏掉的一环。⑥ 收集了 ③④ 之间最容易串味的六组词。

六、容易混淆的六组词 ​

Fiber 与 plugin —— plugin 是型号，Fiber 是"这一次挂载"。同一个 plugin 挂两次得到两个 Fiber。（vendor/cordis/src/fiber.ts:184）

turn 与 step —— step 是一次模型请求，turn 是把若干 step 包起来的边界。turn 可以有零个 step，step 不可能脱离 turn。（docs/architecture.md:65）

SESSION_FORMAT_VERSION 与 SCHEMA_VERSION —— 前者版本化事件词表（当前 0，按 session 存），后者版本化 SQLite 表结构（当前 15，全局）。两者正交，不可互替。（types.ts:56 与 schema.ts:20）

session event 与 agent event —— session event 是持久事实、会落盘、通过 session/event 广播；agent event 携带内存里的活对象、重启即消失。选错域是最常见的架构错误。（docs/architecture.md:57 与 :58）

waterfall 与 serial —— waterfall 必须调 next()，可改写并往下传；serial 没有 next()，只是按序通知。签名不能互抄。（docs/architecture.md:84；vendor/cordis/src/events.ts:32）

storage 接缝与 session 持久化 —— packages/storage/* 是给插件用的通用存储；packages/session/session-persistence-* 专门落会话日志。名字像，职责无关。
